# Декларативная композиция Larena

> **Для кого:** разработчик пакета, страницы или Smart Component. **Результат:**
> собрать интерфейс из JSON через единый путь. **Нормативный источник:**
> `larena-specs/specs/standards/larena-frontend-composition-v1.json` версии
> 1.0.0. **Грамматика:** Framework Composition Recipe 1.0.1.

Larena не вводит собственную копию грамматики Framework. Стандарт
`larena.frontend.composition.v1` закрепляет, как универсальные Recipe и Document
применяются к данным, правам, версиям и пакетам Larena.

```text
системные и пользовательские артефакты
+ структура страницы
+ настройки
+ ссылки на содержимое и файлы
+ права и контекст
→ Layout resolver
→ Framework Recipe и Document
→ серверный HTML и ресурсы
→ неизменяемый снимок
```

## Обязательная граница

Страница, секция и блок используют один рекурсивный JSON-конверт
`LayoutArtifact`. Они различаются полем `kind`, допустимыми компонентами и
именованными слотами. Вложенность не ограничена фиксированными тремя уровнями,
но каждый дочерний узел должен попасть в зарегистрированный слот. Циклы,
дублирующиеся идентификаторы, неизвестные типы, варианты и слоты отклоняются до
активации результата.

Области страницы также регистрируются сервером. Для каждой области допускаются
режимы `inherit`, `replace` и `empty`; команда reset удаляет локальное решение,
а не создаёт ещё одно значение. Источники сайта, раздела и страницы должны
быть различимы по происхождению и ревизии. Клиент не может придумать область,
слот или источник, которого нет в регистрации. Неизвестная область, цикл или
нарушение обязательности останавливают всю сборку до записи новой ревизии и
активации снимка.

Композиционный документ не содержит HTML, CSS, JavaScript, PHP, абсолютные
пути, пароли, токены, session ID, CSRF и персонализированные ошибки. HTML
является результатом серверной сборки, а не источником макета.

## Владельцы

| Область | Владелец |
| --- | --- |
| Recipe, Document, типы, слоты и общие лимиты | SIMAI Framework |
| Артефакты, связи, версии, публикация и снимки | `larena/layout` |
| Компоненты, Smart Components, варианты и ресурсы | `larena/ui` |
| Значения и наследование оформления | `larena/setting` |
| Содержимое и его ревизии | `larena/storage` в Minimal CMS или `larena/content` в соответствующем профиле |
| Логические ссылки на файлы | `larena/filesystem` |
| Смысл входа, MFA и сессия | `larena/auth` |
| Решение о доступе | `larena/access` |
| Защищённая оболочка | `larena/admin` |

Подробные схемы и conformance-набор Framework остаются в документации
Framework (`ui-doc`). Larena хранит точную версию и digest этого внешнего
контракта и не переписывает его нормативный текст.

## Обязательность

Новая интерфейсная функция проходит через Layout и Recipe. Обход допускается
только как зарегистрированное временное исключение с владельцем, сроком и
критерием удаления. Quality gate проверяет Standard Contract, JSON Schema,
type/slot manifests, циклы, запрещённые поля, conformance fixtures и связь с
документацией.
