# Каталог материалов: подтверждённый путь

> **Для кого:** разработчик. **Результат:** проверить путь от установки до
> защищённого списка записей и понять границу дальнейшей разработки.
> **Источники:** core-12 traceability, Root tests и package READMEs. **Статус:**
> проверенная часть описана как инструкция; недоступная часть отмечена явно.

1. Подготовьте entry-приложение и проверьте среду.
2. Создайте первого администратора.
3. Проверьте типизированные поля и записи.
4. Проверьте список, форму и право доступа.
5. Сверьте ограничения файлов, настроек и локализации.

## 1. Подготовьте entry-приложение

Выполните диагностический набор из [начала работы](/start/). Не продолжайте,
если `larena:doctor` сообщает ошибку подключения или отсутствующий обязательный
пакет.

Ожидаемый результат: приложение видит базовый набор пакетов, а небезопасная
установка без launch record блокируется.

## 2. Создайте первого администратора

Для установленного Developer Alpha bundle откройте `/admin/setup`, создайте
первую учётную запись и войдите. Повторный setup после сохранения первой
личности должен перенаправлять на login.

Здесь работают [Auth](/packages/auth/) и [Access](/packages/access/): Auth
удостоверяет личность, Access назначает системную роль Administrator.

## 3. Проверьте типизированные поля и записи

Текущая сборка содержит типы `text`, `number`, `date`, `file` и `relation`, а
также версионированные строковые, целочисленные и логические типы. Их владелец —
[Property](/packages/property/). Сохранение и версии записей принадлежат
[Storage](/packages/storage/).

Проверяемый интеграционный путь находится в Root и запускается полным quality
gate:

```bash
composer quality:full
```

Ожидаемый результат: проходят проверки типизированных полей, мутаций Storage и
корневой композиции. Этот шаг подтверждает реализованный контракт, но не создаёт
новую продуктовую сущность через стабильный публичный генератор.

## 4. Проверьте список и форму

[Dataview](/packages/dataview/) нормализует запрос и описание представления.
[UI](/packages/ui/) разрешает зарегистрированный Smart-компонент, а
[Admin](/packages/admin/) собирает один принятый collection-screen.

Ожидаемый результат: Root browser/интеграционные проверки подтверждают CRUD,
поиск, фильтрацию, контекст и отказ при неверной области. Объявление шести типов
представлений пока не означает наличие шести завершённых интерфейсов.

## 5. Проверьте право доступа

Для существующей тестовой личности решение можно исследовать поддерживаемой
командой Access:

```bash
php artisan larena:access-explain \
  user:admin_identity:1 \
  user:admin_identity:1 \
  storage.record.read \
  --json
```

Точные зарегистрированные операции зависят от сборки. Если указанная операция
не зарегистрирована, Access обязан отказать; сначала получите актуальный список
операций из текущей сборки.

## 6. Файлы, настройки и язык

[Filesystem](/packages/filesystem/) подтверждён на безопасном логическом
файловом сценарии. [Setting](/packages/setting/) имеет durable site-setting
срез. [Lang](/packages/lang/) подтверждает fallback в интеграции, хотя сам
репозиторий пакета остаётся pre-codegen.

## Граница сценария

В текущем двенадцатипакетном контракте нет принятой универсальной команды,
которая создаёт произвольную модель «Материал», её постоянную схему и готовый
admin screen как один стабильный публичный workflow. На этом месте сценарий
заканчивается. Следующая реализация должна начаться с канонического решения в
Specs и точных package contracts, а не с кода, придуманного документацией.
