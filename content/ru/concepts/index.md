# Основные понятия Larena

> **Для кого:** разработчик и администратор. **Результат:** понимание владельцев
> данных, прав и интерфейса. **Источники:** Larena DNA, Specs и проверенная
> core-12 трассировка. **Статус:** проверено для документируемой сборки;
> словарь сверен с кодом 26.10.2026.

## Путь запроса

```text
core → auth → access
            ↓
property → storage → dataview
     filesystem ↗       ↓
setting + lang → layout → ui → admin
```

`core` задаёт общие runtime-контракты и реестр пакетов. `auth` устанавливает
личность, а `access` решает, разрешена ли операция. `property` описывает типы
полей, `storage` хранит версии записей, `filesystem` владеет безопасными
файловыми операциями. `dataview` нормализует запрос и представление данных.
`layout` описывает композицию, `ui` связывает её с зарегистрированными Smart
компонентами, а `admin` собирает защищённый экран. `setting` и `lang` дают
настройки и локализованный текст.

## Словарь

| Термин | Значение в Larena |
| --- | --- |
| Пакет | Модульная единица `larena/*` с явным владельцем, установкой, метаданными и проверками |
| Настройка | Определение и значение по уровням: вся установка → сайт → раздел → страница, язык — отдельное измерение; изменения проходят через черновик и публикацию. Владелец — `setting`. Настройки вида компонентов (колонки, порядок, режим списка) хранятся отдельно, а настройки самого хранилища — его свойства |
| Локализация | Ресурсы интерфейсного текста и правила fallback; владелец — `lang` |
| Свойство | Тип поля с версией: каждый тип сам объявляет свои настройки, возможности и шаблоны, по ним строятся проверка значений и редактор поля. Владелец — `property`; хранилище, настройки и CMS берут типы оттуда |
| Хранилище | Структуры и версии записей с контролируемыми мутациями; публикация — отдельная голова для каждого сайта и языка; для быстрых списков у каждого хранилища своя таблица-витрина |
| Файл | Логический файловый объект и безопасный жизненный цикл |
| Представление данных | Нормализованное описание запроса, колонок, фильтров и вида результата |
| Композиция | Декларативная структура областей и компонентов страницы |
| Компонент | Зарегистрированный тип интерфейса с известным контрактом props и ресурсов |
| Пользователь | Устойчивая личность и сессия, которыми владеет `auth` |
| Право доступа | Решение для зарегистрированной операции, роли и области данных |

## Граница ответственности

Пакет вправе расширять систему через объявленный контракт. Он не должен читать
внутренние таблицы соседнего пакета, подменять его политику или превращать Blade
в слой вычислений. Начните изменение с [границ пакетов](/standards/) и найдите
владельца в [справочнике](/packages/).

Подробная модель артефактов, связей, содержимого и снимков описана на странице
[«Как Larena собирает страницу»](/concepts/page-composition/).
