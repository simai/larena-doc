# `larena/ui`

> **Для кого:** разработчик интерфейса. **Результат:** разрешить только
> зарегистрированный Smart и его зафиксированные ресурсы. **Источник:** код
> пакета (`src/`), `resources/sf/runtime-lock.json`, CHANGELOG, manifests и Specs.
> **Статус:** developer foundation с точным frontend runtime lock; наборы
> компонентов проверены по коду `979a0eca` 26.10.2026.

UI владеет реестром Smart-компонентов, безопасным разрешением view и связью с
зафиксированным frontend artifact. Основные точки текущего среза —
`Larena\Ui\Runtime\SmartManager` и `FrontendRuntimeLock`.

- Composer: `larena/ui`.
- Владелец: Smart registry, rendering and frontend lock.
- Зрелость: developer foundation с exact runtime identity.

Пакет зависит от Core, Dataview и Layout. Тип компонента, props и ресурсы должны быть
объявлены в реестре; произвольный класс или путь шаблона не является допустимым
компонентом.

## Наборы компонентов

Кроме бесплатного SIMAI Framework, Larena использует набор Smart-компонентов
`larena`: таблицы, представление данных, карточку записи, меню администратора,
компоненты переписки и другие. Набор собирается из `simai/ui-pro`, а готовые
архивы выпускаются в релизах `simai/larena-ui`.

Frontend runtime lock (`resources/sf/runtime-lock.json`) фиксирует точный релиз
Framework и точный релиз набора: коммит, хеши архива, манифеста и квитанции,
а также релиз Framework, который нужен набору. Только lock задаёт точные
версии.

Файлы наборов приходят внутри дистрибутива Larena и через обновления; сайт
отдаёт их сам. С CDN они никогда не загружаются.

Решение владельца от 26.10.2026: отдельных продуктовых наборов нет, у всех
компонентов один префикс `sf-`, а сами компоненты делаются только во Framework
и в `simai/ui-pro`.

### Как пакету объявить нужный набор

Пакет указывает нужные наборы в своём `composer.json`:

```json
"extra": {
  "larena": {
    "component_packages": {
      "larena": {
        "releases": "*",
        "release_repository": "simai/larena-ui",
        "source_repositories": ["simai/larena-ui", "simai/ui-admin", "simai/ui-pro"]
      }
    }
  }
}
```

`"*"` принимает любой релиз, который закреплён в lock; список релизов
принимает только их. Диапазонов нет: у коммитов нет порядка.

`ComponentPackageRequirements` сверяет объявления установленных пакетов с lock
и отказывает, если набор не закреплён, его релиз не принят, он собран или
выпущен не из того репозитория, требует другого релиза Framework или у него нет
хешей. Закреплённый набор, который никто не объявил, не ошибка: он просто
попадает в отчёт. Проверка запускается командой
`composer run component-packages:check` и входит в quality gate пакета.

## Проверка

Root exact-release validator сравнивает UI revision с lock, а integration test
проверяет Smart render. Совпадение lock подтверждает идентичность ресурсов, а
не полноту всех интерфейсных состояний.

## Роль в композиции

UI владеет реестром допустимых компонентов, Smart backend renderers, вариантами,
именованными слотами и ресурсами. UI не хранит дерево страницы. Точная поставка
Framework проверяется по Git-ревизиям, manifest и digest; сгенерированные
артефакты вручную не редактируются.

## Маршруты между списками

UI связывает тип `larena.registered-list` с опубликованным элементом
`sf-table`, который владеет портами `selection` и `context`. В статическом
снимке остаётся только контейнер списка с именем endpoint; строки подставляются
при каждом запросе с правами пользователя. Хост списка, который является целью
маршрута, начинает с пустого состояния, превращает переданный выбор в один
серверный запрос с фильтром по идентификаторам записей и отвечает таблице через
её номер последовательности, поэтому устаревший ответ не заменяет новые строки.
Принято в UI `main` на ревизии `cb0aff0c60d468403064c81fe6ca79c86e025145` с
парой Framework `ui-2b9aa9635ad0-smart-db547bb87b6b`.
Текущий frontend lock UI закрепляет Framework `ui-357568a20a7e` и набор
`larena-9cbe0610b74b`; в нём зарегистрированы `sf-data-view` и атрибут
`row-actions` таблицы `sf-table`.
