# `larena/ui`

> **Для кого:** разработчик интерфейса. **Результат:** разрешить только
> зарегистрированный Smart и его зафиксированные ресурсы. **Источник:** код
> пакета (`src/`), `resources/sf/runtime-lock.json`, CHANGELOG, manifests и Specs.
> **Статус:** developer foundation с точным frontend runtime lock; наборы
> компонентов проверены по коду `eced1374` 18.11.2026.

UI владеет реестром Smart-компонентов, безопасным разрешением view и связью с
зафиксированным frontend artifact. Основные точки текущего среза —
`Larena\Ui\Runtime\SmartManager` и `FrontendRuntimeLock`.

- Composer: `larena/ui`.
- Владелец: Smart registry, rendering and frontend lock.
- Зрелость: developer foundation с exact runtime identity.

Пакет зависит от Core и Dataview; Layout необязателен (его рецепты называют
те же утилиты коллекций). Тип компонента, props и ресурсы должны быть
объявлены в реестре; произвольный класс или путь шаблона не является допустимым
компонентом.

## Наборы компонентов

Кроме бесплатного SIMAI Framework, Larena использует наборы Smart-компонентов:

- `pro` — таблицы, представление данных, карточка записи, меню
  администратора, компоненты переписки и другие. Собирается из `simai/ui-pro`
  и выпускается там же релизами `pro-<12 знаков>`. До 03.11.2026 этот набор
  назывался `larena` и выпускался в `simai/larena-ui`; те архивы остаются
  историей.
- `chart` — графики SIMAI Chart из `simai/ui-chart`.

Frontend runtime lock (`resources/sf/runtime-lock.json`) фиксирует точный релиз
Framework и точный релиз каждого набора: коммит, хеши архива, манифеста и
квитанции, а также релиз Framework, над которым набор собран. Только lock
задаёт точные версии.

Файлы наборов приходят внутри дистрибутива Larena и через обновления; сайт
отдаёт их сам. С CDN они никогда не загружаются.

Компоненты делаются только во Framework и в наборах; у всех один префикс
`sf-`. С 03.11.2026 действуют новые имена тегов Framework: `sf-view-table`
(было `sf-table`), `sf-view` (было `sf-data-view`), `sf-view-properties`
(было `sf-property-view`), `sf-button-icon` (было `sf-icon-button`). Ключ
настроек вида `sf-table` остаётся прежним.

### Набор над более новым Framework

Набор, собранный над одним релизом Framework, можно закрепить над более
новым двумя способами; в записи набора в lock бывает только один из них:

- **квитанция пары** (`pair_receipt`) — для набора, чьи собственные байты не
  изменились: файл `pair-receipt-<пара>.json` из релиза набора с закреплённым
  sha256 называет тот же релиз, архив, манифест и квитанцию и новую пару
  Framework;
- **диапазон пары** (`pair_range`) — файл `pair-range.json` из релиза набора:
  проверка (`set-pair-range` из `simai/ui-builder`) подтверждает, что каждое
  требование набора выполняется над закреплённым Framework (`checked_over`).

Браузерные проверки Larena при перезакреплении обязательны и для набора,
принятого по диапазону.

### Как пакету объявить нужный набор

Пакет указывает нужные наборы в своём `composer.json`, например Admin:

```json
"extra": {
  "larena": {
    "component_packages": {
      "pro": {
        "releases": "*",
        "release_repository": "simai/ui-pro",
        "source_repositories": ["simai/ui-pro"]
      }
    }
  }
}
```

Storage так же объявляет `chart` из `simai/ui-chart`.

`"*"` принимает любой релиз, который закреплён в lock; список релизов
принимает только их. Диапазонов релизов нет: у коммитов нет порядка.

`ComponentPackageRequirements` сверяет объявления установленных пакетов с lock
и отказывает, если набор не закреплён, его релиз не принят, он собран или
выпущен не из того репозитория, требует другого релиза Framework без
квитанции или диапазона пары или у него нет хешей. Закреплённый набор, который
никто не объявил, не ошибка: он просто попадает в отчёт. Проверка запускается
командой `composer run component-packages:check` и входит в quality gate
пакета.

## Проверка

Root exact-release validator сравнивает UI revision с lock, а integration test
проверяет Smart render. Совпадение lock подтверждает идентичность ресурсов, а
не полноту всех интерфейсных состояний.

## Роль в композиции

UI владеет реестром допустимых компонентов, Smart backend renderers, вариантами,
именованными слотами и ресурсами. UI не хранит дерево страницы. Точная поставка
Framework проверяется по Git-ревизиям, manifest и digest; сгенерированные
артефакты вручную не редактируются.

## Маршруты между списками

UI связывает тип `larena.registered-list` с опубликованным элементом
`sf-view-table`, который владеет портами `selection` и `context`. В статическом
снимке остаётся только контейнер списка с именем endpoint; строки подставляются
при каждом запросе с правами пользователя. Хост списка, который является целью
маршрута, начинает с пустого состояния, превращает переданный выбор в один
серверный запрос с фильтром по идентификаторам записей и отвечает таблице через
её номер последовательности, поэтому устаревший ответ не заменяет новые строки.
Принято в UI `main` на ревизии `cb0aff0c60d468403064c81fe6ca79c86e025145` с
парой Framework `ui-2b9aa9635ad0-smart-db547bb87b6b`.
Текущий frontend lock UI закрепляет Framework `ui-7fb26d395af2` и наборы
`pro-db490626ba74` и `chart-58ba480db497`, оба приняты над этим Framework по
диапазону пары.
