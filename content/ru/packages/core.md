# `larena/core`

> **Для кого:** разработчик платформы. **Результат:** понять общий runtime и
> безопасную границу операций. **Источник:** код пакета (`src/`), package
> README, module manifest, Specs и Root integration. **Статус:** contract
> foundation; интеграционный реестр, ограниченный runtime, области и SitePack
> проверены по коду `37a3775e` 26.10.2026.

Core задаёт фундаментальные DTO, интерфейсы и правила исполнения операций. Он
не владеет пользовательским интерфейсом, правами конкретного домена или данными
другого пакета.

Core также хранит системные записи областей (сайт, организация), плоскостей,
узлов и членства. Они не несут бизнес-смысла; права на узлах назначает Access.

- Composer: `larena/core`.
- Владелец: общий runtime и package registry foundation.
- Зрелость: contract foundation с Root integration evidence.

## Зависимости и точки входа

Пакет требует PHP 8.3 и Illuminate 13. Ключевая точка текущего среза —
`Larena\Core\Runtime\SyncOperationRuntime`; контрактная граница включает
`OperationRuntime` и DTO операции, контекста, решения и результата. Каждая
операция Core объявлена один раз в `operations.yaml` с риском, обратимостью,
правом и схемами и попадает в единый реестр; неполное описание реестр
отклоняет. Операции реестра исполняются и внутри приложения, не только через
REST. Сетевой транспорт пока только объявлен как интерфейс.

Сервис-провайдер Core собран из отдельных регистраторов
(`Larena\Core\Providers\Registrars`): модель областей, операции, среда и
установка. Поведение от этого не меняется, но каждую часть проще найти.

Минимальное использование происходит через пакет, который регистрирует свою
операцию и передаёт её Core runtime. Неизвестный или небезопасный режим должен
завершаться отказом.

## Области

Пользователь или другой субъект может состоять сразу в нескольких областях.
Первая область, в которую он вступил, становится областью по умолчанию; её
можно сменить через `setDefault`. Если членство отозвано, умолчание переходит к
следующей области субъекта. Всё это даёт `ScopeMembershipRegistry`: назначить,
отозвать, проверить членство, получить список областей постранично с поиском.
Членство само по себе прав не даёт — права остаются у Access.

Ресурс, например логический файл (`filesystem.logical_file`), привязывается
ровно к одной области через `ScopeResourceBindings`. Повторная привязка к той же
области ничего не меняет, привязка к другой отклоняется. Так Access может
понять, чьей области принадлежит ресурс, не читая таблицы владельца.

Старая ссылка вида `scope:<id>` пока остаётся в сохранённых данных как
псевдоним области (`ScopeLegacyAliases`). У области не больше одного такого
псевдонима; `siteForLegacyRef` при первом обращении создаёт для старой ссылки
сайт. Перевод данных на собственные ссылки областей — отдельный будущий шаг.

## SitePack

Core задаёт общий конверт SitePack (`Larena\Core\SitePack`): манифест и
каталог, где у каждого артефакта есть путь, размер и SHA-256. Идентификатор
пакета вычисляется из каталога, поэтому манифест привязан ровно к этому набору
файлов.

`SitePackArchiveWriter` пишет архив, не держа его в памяти, и собирает
одинаковый zip для одинакового содержимого. `SitePackArchiveReader` читает
артефакты потоком и сверяет размер, число строк и хеш. Ещё при открытии он
отклоняет зашифрованные, повторяющиеся и неизвестные записи, символические
ссылки, небезопасные пути и подозрительно сильное сжатие.

Пределы задаёт `SitePackLimits` и раздел `sitepack` в `config/larena-core.php`
(переменные `LARENA_SITEPACK_MAX_*`): общий размер, число записей, длина строки,
глубина JSON, степень сжатия и размер документа. Значения по умолчанию рассчитаны
на архивы в гигабайты; они защищают от сломанных и враждебных архивов.

Core даёт только конверт и чтение/запись архива. Что именно кладётся в пакет и
как он применяется, решают пакеты-участники; сейчас конверт использует Storage.

## Имена без версий

Имена форматов, отчётов и классов не содержат номера версии. Версия хранится
полем данных: `{"schema": "<имя>", "schema_version": N}`. Так подписаны реестр
пакетов и его резервная копия, состояние установщика, резервные копии и
квитанция маршрутов. Данные, записанные раньше в форме `<имя>.vN`, продолжают
читаться: для этого все читатели используют одну проверку
`Larena\Core\Support\SchemaName`.

## Проверка

В entry-приложении выполните `php artisan larena:runtime-security-smoke`.

Команда `php artisan core:operations:coverage` показывает покрытие реестра
операций и проверяет структуру файлов описаний всех установленных пакетов.
`larena:doctor` дополнительно выводит раздел среды: возможности хоста, которые
не удалось определить, считаются отсутствующими, а расхождение с объявленным
профилем только сообщается и не делает проверку проваленной.
Полный Root quality gate дополнительно проверяет Minimal CMS dependency closure
и состав реестра.

## Ограничение

Package README всё ещё описывает часть Core как contract skeleton без
собственной production persistence, хотя области, членство и привязки ресурсов
уже хранятся в собственных таблицах Core. Не используйте интеграционную готовность
Root как обещание автономной готовности всех поверхностей Core.
