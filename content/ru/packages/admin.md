# `larena/admin`

> **Для кого:** разработчик admin-функций. **Результат:** собрать экран из
> владельцев данных, прав и UI. **Источник:** package README, Specs и Root
> browser evidence. **Статус:** проверенный ограниченный редактор композиции.

Admin собирает навигацию, контроллер, presenter и package contributions. Он не
забирает семантику Auth, Access, Storage, Property, Dataview, Layout или UI.

- Composer: `larena/admin`.
- Владелец: protected admin composition.
- Зрелость: ограниченные рабочие разделы — Minimal CMS и «Хранилища».

Текущие точки принятого Minimal CMS пути —
`Larena\Admin\Http\Controllers\MinimalCmsController` и
`Larena\Admin\Runtime\MinimalCmsSmartPagePresenter`.

Пакет зависит от остальных одиннадцати пакетов, что отражает роль оркестратора.

## Раздел «Хранилища»

Раздел `/admin/storage` показывает хранилища и их записи. Он включён во всех
окружениях; отключить его можно переменной `LARENA_ADMIN_STORAGE_SECTION=false`
(ключ `larena-admin.storage_section`). В меню это группа «Хранилище», пункт
«Хранилища». Записи открываются по адресу `/admin/storage/{хранилище}`, поля —
на странице `/admin/storage/{хранилище}/settings`. Раздел читает и меняет данные
только через Storage, каждое действие проверяет Access. Страница разработчика
`/admin/storage-workbench` остаётся стендом без пункта меню и работает только в
локальном и тестовом окружении.

## Общая страница списка

Все списки Admin собираются одним presenter —
`Larena\Admin\Runtime\AdminDataviewPagePresenter` на основе Framework
`sf-data-view`. У строк одно общее меню действий (просмотр, изменение,
удаление, восстановление). Запись открывается в правой панели
(`AdminRecordPanelPresenter`) для просмотра, изменения и создания; архивация,
восстановление и окончательное удаление выполняются там же с подтверждением.
Поля «Пользователь» и «Файл» выбираются из постраничного списка вариантов своей
области. Правила записаны в
[стандарте страницы с представлением данных](/standards/admin-dataview-page/).

## Учётная запись и администраторы

Admin отображает экраны `/admin/security` (своя MFA и сессии), а при полном
профиле Auth — `/admin/users` и `/admin/security/diagnostics`. Личность и
проверку входа по-прежнему выполняет Auth, роли — Access.

## Проверка

Root browser и integration evidence подтверждают CRUD, контекст, права и один
явно объявленный collection-screen. Прямой URL без разрешения должен дать
отказ или перенаправление на вход.

## Ограничение

Текущий редактор работает только с зарегистрированными сервером целями и
каталогами. Он поддерживает две демонстрационные страницы, вложенные экземпляры,
публикацию, откат и смену совместимого источника выбранного независимого блока.
Источники передаются в браузер как непрозрачные ключи; реальную привязку и права
проверяет сервер. Это ещё не универсальный конструктор всех административных
страниц и не интерфейс настройки произвольных внешних подключений.

## Композиционный контейнер

Admin предоставляет защищённую оболочку и адаптер страницы входа. Для
`/admin/login` он связывает Auth presenter, Layout resolver и Smart backend
renderers. Blade остаётся тонким контейнером серверного HTML. Остальные экраны
переносятся отдельными вертикальными срезами после собственной приёмки.

Для `/admin/composition-editor` Admin также предоставляет presenter полей
Framework и локализованную оболочку. Значения и команды по-прежнему проверяет
Layout; Admin не становится владельцем макета, содержимого или публикации.
Поля группируются по метаданным Framework как предустановки, основные и
расширенные. Admin только отображает эти группы и происхождение значения.
