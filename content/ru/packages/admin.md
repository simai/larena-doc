# `larena/admin`

> **Для кого:** разработчик admin-функций. **Результат:** собрать экран из
> владельцев данных, прав и UI. **Источник:** код пакета (`src/`, `routes/`,
> `config/`, `52761774`), CHANGELOG, package README и Specs (раздел «Хранилища»,
> шифрование полей, перенос хранилища). **Статус:** проверенный ограниченный
> редактор композиции и рабочий раздел «Хранилища»; проверено по коду
> 26.10.2026.

Admin собирает навигацию, контроллер, presenter и package contributions. Он не
забирает семантику Auth, Access, Storage, Property, Dataview, Layout или UI.

- Composer: `larena/admin`.
- Владелец: protected admin composition.
- Зрелость: ограниченные рабочие разделы — Minimal CMS и «Хранилища».

Текущие точки принятого Minimal CMS пути —
`Larena\Admin\Http\Controllers\MinimalCmsController` и
`Larena\Admin\Runtime\MinimalCmsSmartPagePresenter`.

Пакет зависит от остальных одиннадцати пакетов, что отражает роль оркестратора.
Набор компонентов Framework, который ему нужен (`sf-table`, `sf-data-view`,
`sf-property-view`, `sf-admin-menu`), пакет объявляет в `composer.json`
(`extra.larena.component_packages`).

## Маршруты

Рабочая админка (`/admin`, Minimal CMS, «Хранилища», редакторы структуры и
стенд `/admin/storage-workbench`) загружается из `routes/admin-product.php`
во всех окружениях. Каждый раздел включается своим ключом конфигурации, а сам
вход в админку — настройкой входа. Отдельного запасного экрана у `/admin` нет.
Флаг `LARENA_ADMIN_INTERNAL_PREVIEW_ROUTES` управляет только страницами для
разработчика; их осталось немного: вход `/larena/internal/developer-preview` и
пять живых демо-стендов, только в локальном и тестовом окружении.

## Раздел «Хранилища»

Раздел `/admin/storage` показывает хранилища и их записи. Он включён во всех
окружениях; отключить его можно переменной `LARENA_ADMIN_STORAGE_SECTION=false`
(ключ `larena-admin.storage_section`). В меню это группа «Данные», пункт
«Хранилища». Записи открываются по адресу `/admin/storage/{хранилище}`, поля —
на странице `/admin/storage/{хранилище}/settings`. Раздел читает и меняет данные
только через Storage, каждое действие проверяет Access. Страница разработчика
`/admin/storage-workbench` остаётся стендом без пункта меню и работает только в
локальном и тестовом окружении. Как с разделом работает администратор, описано
в [руководстве по хранилищам](/cms/storage/).

Что умеет раздел:

- **Список записей** идёт из витрины Storage: без выбранной сортировки —
  «сначала новые» (`StorageListOrder`), в большом хранилище — оценка «~N» с
  кнопкой «Посчитать точно», подсказка о медленной сортировке по полю без
  индекса (`StorageSortHint`) и «Список готовится», пока витрина строится.
- **Редактор полей** строится из объявленных настроек типа Property
  (`PropertyTypeSettingsForm`): показываются только настройки выбранного типа, а
  те, что задаются при создании, потом только читаются. Предлагаются все типы
  каталога Property, включая «Выбор из справочника», «Цвет», «Телефон», «Адрес
  страницы» и «Ссылка».
- **Изменение, затрагивающее данные,** сначала проверяется по записям
  (`structure.configure_check`): строка сохранения спрашивает «Новые настройки
  затронут данные: проверено M из T записей, не подходят N» и выполняет
  изменение только с отпечатком этого вопроса. Большое хранилище меняется в
  фоне, ход виден на странице, есть «Отменить изменение».
- **Шифрование полей:** «Шифровать» в редакторе, «•••• зашифровано» в списках,
  «Показать» для права `storage.workbench.record.decrypt`, блок «Шифрование» с
  состоянием ключа и «Сменить ключ шифрования» для `storage.encryption.manage`.
- **CSV:** быстрый экспорт видимых колонок, экспорт и импорт в фоне на странице
  «Фоновые задачи»; импорт сначала показывает план изменений.
- **Перенос на другой сайт:** «Выгрузить хранилище» на странице настроек и
  «Загрузить хранилище» в списке хранилищ — с планом, отпечатком плана,
  черновиками по умолчанию, отменой и повтором.
- **Фоновая работа** обновляется на странице сама, без перезагрузки
  (`AdminLiveRegion`): задачи CSV, перенос, изменение поля и шифрование.

Ограничения раздела: поле «Ссылка» в панели записи показывается только для
чтения, пока во Framework нет элемента для ввода ссылки; ссылки не фильтруются.
Поля-ссылки (пользователь, файл, запись) из CSV пока не импортируются.

## Общая страница списка

Все списки Admin собираются одним presenter —
`Larena\Admin\Runtime\AdminDataviewPagePresenter` на основе Framework
`sf-data-view`. У строк одно общее меню действий (просмотр, изменение,
удаление, восстановление). Запись открывается в правой панели
(`AdminRecordPanelPresenter`) для просмотра, изменения и создания без
перезагрузки страницы; архивация, восстановление и окончательное удаление
выполняются там же с подтверждением. Поля «Пользователь», «Файл», «Запись
хранилища» и «Выбор из справочника» выбираются из постраничного списка
вариантов своей области или своего источника. Правила записаны в
[стандарте страницы с представлением данных](/standards/admin-dataview-page/).

Настройки колонок, профили списка и раскладки записи хранятся в хранилище
настроек вида пакета Setting; общий профиль для роли может назначить только
тот, у кого есть право `access.role.update`.

## Учётная запись и администраторы

Admin отображает экраны `/admin/security` (своя MFA и сессии), а при полном
профиле Auth — `/admin/users` и `/admin/security/diagnostics`. Личность и
проверку входа по-прежнему выполняет Auth, роли — Access.

## Мониторинг

Если установлен пакет мониторинга, в группе «Сервис» есть страница
`/admin/monitoring`: метрики пакетов за сутки, 7 или 30 дней — число событий,
p50 и p95, доля ошибок и состояние («Работает», «Деградирует», «Не
используется», «Нет данных»). Страница только читает метрики.

## Проверка

Root browser и integration evidence подтверждают CRUD, контекст, права и один
явно объявленный collection-screen. Прямой URL без разрешения должен дать
отказ или перенаправление на вход.

## Ограничение

Текущий редактор работает только с зарегистрированными сервером целями и
каталогами. Он поддерживает две демонстрационные страницы, вложенные экземпляры,
публикацию, откат и смену совместимого источника выбранного независимого блока.
Источники передаются в браузер как непрозрачные ключи; реальную привязку и права
проверяет сервер. Это ещё не универсальный конструктор всех административных
страниц и не интерфейс настройки произвольных внешних подключений.

## Композиционный контейнер

Admin предоставляет защищённую оболочку и адаптер страницы входа. Для
`/admin/login` он связывает Auth presenter, Layout resolver и Smart backend
renderers. Blade остаётся тонким контейнером серверного HTML. Остальные экраны
переносятся отдельными вертикальными срезами после собственной приёмки.

Для `/admin/composition-editor` Admin также предоставляет presenter полей
Framework и локализованную оболочку. Значения и команды по-прежнему проверяет
Layout; Admin не становится владельцем макета, содержимого или публикации.
Поля группируются по метаданным Framework как предустановки, основные и
расширенные. Admin только отображает эти группы и происхождение значения.
