# `larena/admin`

> **Для кого:** разработчик admin-функций. **Результат:** собрать экран из
> владельцев данных, прав и UI. **Источник:** код пакета (`src/`, `routes/`,
> `config/`, `c3fa8fd6`), CHANGELOG, package README и Specs. **Статус:**
> рабочая админка Larena CMS и проверенный ограниченный редактор композиции;
> проверено по коду 18.11.2026.

Admin собирает навигацию, контроллер, presenter и package contributions. Он не
забирает семантику Auth, Access, Storage, Property, Dataview, Layout или UI.

- Composer: `larena/admin`.
- Владелец: protected admin composition.
- Зрелость: рабочая админка Larena CMS — главная, страницы сайта, сайты и их
  настройки, черновики и публикация, люди и роли; раздел «Хранилища» приносит
  Storage.

Демонстрационный экран Minimal CMS (`/admin/cms`) с его блоками и конструктором
страниц удалён 29.10.2026.

Обязательные зависимости: `larena/access`, `larena/audit`, `larena/auth`,
`larena/core`, `larena/dataview`, `larena/filesystem`, `larena/property`,
`larena/setting` и `larena/ui`. Необязательные:

- `larena/storage` — экран «Страницы сайта» (`/admin/site/pages`) и раздел
  «Хранилища» (`/admin/storage`), который приносит сам Storage; без него
  админка работает без них;
- `larena/layout` — сборка страниц: блоки сайта, страница входа по её рецепту и
  страницы разработчика `/admin/ui`; без него страница входа рисуется из
  готового документа;
- `larena/lang` — названия языков, из которых сайт выбирает свои; без него
  выбор идёт из настроенных языков по коду;
- `larena/monitoring` и `larena/notification` — страницы `/admin/monitoring` и
  `/admin/notifications`.

Набор компонентов, который нужен админке, — `pro` из `simai/ui-pro`
(`sf-view-table`, `sf-view`, `sf-view-properties`, `sf-admin-menu` и другие);
пакет объявляет его в `composer.json` (`extra.larena.component_packages`).

## Как собираются страницы

Контроллеры и presenter-ы admin отдают типизированные описания страницы:
заголовок с кнопками и пометками, узлы разметки, элементы Framework и готовые
части владельцев. HTML строит общий `RegisteredDocumentRenderer` пакета UI,
большие страницы он делит на несколько документов с той же разметкой.
Шаблоны Blade остаются тонкими: они печатают готовый результат через `{{ }}` и
не склеивают фрагменты. В рабочих шаблонах нет `{!! !!}`; тест
`AdminBladeThinHostRatchetTest` не даёт вернуть такой вывод.

## Маршруты

Рабочая админка (`/admin` и её разделы, редакторы структуры) загружается из
`routes/admin-product.php` во всех окружениях; раздел «Хранилища» и стенд
`/admin/storage-workbench` регистрирует Storage. Каждый раздел включается своим
ключом конфигурации, а сам вход в админку — настройкой входа.

Функции админки выбирает продукт в `config/larena-product.php` (`features`):
`admin.groups`, `admin.site_pages`, `admin.settings.overview`,
`admin.settings.sites`, `admin.settings.catalog`, `admin.settings.changes`,
`admin.roles_editor` и `admin.site_switcher` (`config/features.php`). Без выбора
включено всё; у выключенной функции нет маршрутов и пунктов меню. Продукт
объявляет и корни меню. Отдельного запасного экрана у `/admin` нет.
Флаг `LARENA_ADMIN_INTERNAL_PREVIEW_ROUTES` управляет только страницами для
разработчика; их осталось немного: вход `/larena/internal/developer-preview` и
пять живых демо-стендов, только в локальном и тестовом окружении.

## Раздел «Хранилища»

С 29.10.2026 раздел `/admin/storage` — интерфейс пакета Storage: его
контроллеры, маршруты и тексты живут в `larena/storage` и регистрируются,
только когда установлен Admin. Ключ конфигурации и переключатель прежние:
`larena-admin.storage_section`, `LARENA_ADMIN_STORAGE_SECTION=false`. Admin
оставляет за собой общие швы: порядок поиска, отказы при выборе вариантов
записи, маску зашифрованного значения и структуры меню. Что умеет раздел,
описано на странице [Storage](/packages/storage/) и в
[руководстве по хранилищам](/cms/storage/).

## Части админки от пакетов

Пакеты добавляют в админку свои части через контракты Admin:

- `AdminAlertSource` — строка важных состояний над шапкой: то, что требует
  действия сейчас и пока длится причина (полный диск, неотвечающий сайт,
  неудачная копия). События, которые просто случились, идут в центр
  уведомлений. Скрытое предупреждение возвращается через сутки, скрытые
  сведения не возвращаются, опасность скрыть нельзя;
- `AdminFirstStepsSource` — пункты «Первых шагов» на главной (`home`) со
  своей проверкой «сделано» и кнопкой действия; человек может скрыть список
  для себя;
- `AdminObjectMenuSource` — меню открытого объекта во второй колонке меню
  (разделы сайта, части записи): не больше двух меню, второе — о том, где
  человек сейчас.

Мастера установки — веб-установка и первый запуск — показываются одним
мастером «Установка Larena» по шагу на странице (`InstallWizard`): база,
проверка, установка, администратор, сайт, готово. Если база пришла со сборкой,
первые три шага пропускаются. Опасные действия спрашивают подтверждение в окне
вопроса Framework, а не отметкой «Подтверждаю»; действие с планом показывает
план, вопрос, ход и итог в боковой панели (`AdminPlannedAction`).

## Общая страница списка

Все списки Admin собираются одним presenter —
`Larena\Admin\Runtime\AdminDataviewPagePresenter` на основе Framework
`sf-view`. У строк одно общее меню действий (просмотр, изменение,
удаление, восстановление). Запись открывается в правой панели
(`AdminRecordPanelPresenter`) для просмотра, изменения и создания без
перезагрузки страницы; архивация, восстановление и окончательное удаление
выполняются там же с подтверждением. Поля «Пользователь», «Файл», «Запись
хранилища» и «Выбор из справочника» выбираются из постраничного списка
вариантов своей области или своего источника. Правила записаны в
[стандарте страницы с представлением данных](/standards/admin-dataview-page/).

Панель записи читает запись по группам (порт `simai.property-view-port`
1.15.0, `group.load`). Первый ответ несёт заголовок записи, всю раскладку
разделов и групп и поля только той группы, с которой открывается панель.
Остальные группы приходят без полей, с числом полей, и дочитываются, когда
человек открывает их раздел. Версия у записи одна на все группы. Поэтому
сохранение группы после того, как запись изменили в другой группе,
получает конфликт с текущей версией, и введённое не теряется.

Настройки колонок, профили списка и раскладки записи хранятся в хранилище
настроек вида пакета Setting; общий профиль для роли может назначить только
тот, у кого есть право `access.role.update`.

## Учётная запись и администраторы

Admin отображает экраны `/admin/security` (своя MFA и сессии), а при полном
профиле Auth — `/admin/users` и `/admin/security/diagnostics`. Личность и
проверку входа по-прежнему выполняет Auth, роли — Access.

## История

Страница «История» (`/admin/history`, последний пункт верхнего меню) — одна
лента того, что делали на сайте: сверху «Идёт сейчас», ниже сделанное по
дням словами — кто, что, над чем, с каким итогом. Строка открывает подробности
в боковой панели, коды видны только в «Подробно». Отборы: объект, человек,
итог и «Безопасность» (входы и отказы в доступе). Старый адрес `/admin/audit`
ведёт сюда. Пакеты добавляют в ленту свои события через контракт
`AdminHistorySource`.

## Мониторинг

Если установлен пакет мониторинга, в группе «Сервис» есть страница
`/admin/monitoring`: метрики пакетов за сутки, 7 или 30 дней — число событий,
p50 и p95, доля ошибок и состояние («Работает», «Деградирует», «Не
используется», «Нет данных»). Страница только читает метрики.

## Проверка

Root browser и integration evidence подтверждают CRUD, контекст, права и один
явно объявленный collection-screen. Прямой URL без разрешения должен дать
отказ или перенаправление на вход.

## Ограничение

Текущий редактор работает только с зарегистрированными сервером целями и
каталогами. Он поддерживает две демонстрационные страницы, вложенные экземпляры,
публикацию, откат и смену совместимого источника выбранного независимого блока.
Источники передаются в браузер как непрозрачные ключи; реальную привязку и права
проверяет сервер. Это ещё не универсальный конструктор всех административных
страниц и не интерфейс настройки произвольных внешних подключений.

## Композиционный контейнер

Admin предоставляет защищённую оболочку и адаптер страницы входа. Для
`/admin/login` он связывает Auth presenter, Layout resolver и Smart backend
renderers. Blade остаётся тонким контейнером серверного HTML. Остальные экраны
переносятся отдельными вертикальными срезами после собственной приёмки.

Для `/admin/composition-editor` Admin также предоставляет presenter полей
Framework и локализованную оболочку. Значения и команды по-прежнему проверяет
Layout; Admin не становится владельцем макета, содержимого или публикации.
Поля группируются по метаданным Framework как предустановки, основные и
расширенные. Admin только отображает эти группы и происхождение значения.
