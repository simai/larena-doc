# `larena/property`

> **Для кого:** разработчик схем данных и форм. **Результат:** выбрать точный
> `type@version`, задать его настройки и проверить значение до сохранения.
> **Источник:** код пакета (`5ae11ae7`), CHANGELOG и Specs: стандарт типов
> свойств и система настроек. **Статус:** package-owned foundation: реестр типов
> и описание поля есть, значения пакет не хранит.

Property владеет реестром типов, их настройками, нормализацией, валидацией и
описанием поля для панели свойств. Текущий реестр (снимок версии 7) содержит:

- строки и текст: `string@1`, безопасный `string@2`, `text@1`;
- числа и даты: `integer@1`, `number@1`, `date@1`, `datetime@1` (локальные дата
  и время), `boolean@1`;
- выбор: `choice@1` (один вариант из списка), `choices@1` (несколько вариантов),
  `lookup@1` («Выбор из справочника»);
- ссылки на объекты: `file@1`, `relation@1`, `user@1`, `record@1` (запись другой
  структуры Storage);
- цвет, контакты и адреса: `color@1`, `phone@1`, `url@1`, `link@1`.

Если задача сформулирована как «создать поле», сначала выберите точный
`type@version`, затем задайте его настройки и выполните нормализацию и серверную
валидацию.

- Composer: `larena/property`.
- Владелец: type registry, настройки типов, normalization and validation.
- Зрелость: foundation без хранения значений.

## Точка входа

Используйте `Larena\Property\Runtime\PropertyTypeRegistry` и выбирайте версию
явно. Нормализация и валидация являются отдельными серверными операциями; перед
записью можно применить их как единый fail-closed шаг. Реестр из контейнера уже
связан с источниками вариантов, поэтому проверяет и значения `lookup@1`.

## Настройки типа

Каждый тип сам объявляет свои настройки в одном месте —
`PropertyTypeSettingsCatalog`. Прочитать их можно через
`PropertyTypeRegistry::settings()`. Storage, Admin и редактор поля берут список
типов и настроек оттуда, а не держат свой.

Каждая настройка (`PropertySettingDescriptor`) говорит:

- ключ, вид значения, значение по умолчанию и ключ подписи;
- где она действует (`acts_on`): на данные, в форме, в фильтре, в списке;
- можно ли менять её после создания поля: свободно (`free`), только после
  проверки существующих записей (`checked`) или никогда (`locked`);
- границы и шаблон допустимого значения.

Что есть у типов сейчас:

- `string` и `text`: `min_length`, `max_length`, маска ввода `mask`,
  подсказка `placeholder`;
- `integer`, `number`, `date`, `datetime`: `min` и `max`; у `number` ещё шаг
  `step` и единица `unit`;
- `choice` и `choices`: варианты `options`; у `choices` ещё `max_items`;
- `file`: допустимые форматы `accept` и размер `max_size` — их проверяет
  загрузка, а не валидация значения;
- `record`: обязательная структура `target_structure_id`, после создания не
  меняется;
- `lookup`: обязательный источник `source`, после создания не меняется;
- `phone`: страна по умолчанию `default_country`.

Маска, подсказка, шаг и единица не меняют сохранённые данные.
`PropertyTypeSettings::dataChangingKeys()` называет настройки, изменение которых
затрагивает данные, — только для них нужна проверка или перенос записей.

Тип также объявляет свои возможности: поиск, сортировку, фильтр, индекс,
шифрование. Есть ещё две: `reference` — значение указывает на другой объект
(`user`, `file`, `relation`, `record`), и `auto_indexed` — хост индексирует поле
сам, без отдельной просьбы.

## Новые типы

- `lookup@1` — значение из длинного списка, который ведёт его владелец. Список
  регистрируется как источник вариантов (`PropertyOptionSource`) в
  `PropertyOptionSourceRegistry`. Значение — простой идентификатор, который
  источник подтверждает. Варианты можно получать постранично с поиском
  (`cursorPage()`, не больше 100 за раз).
- `color@1` — цвет `#RRGGBB` или `#RRGGBBAA`. Короткая или строчная запись
  приводится к полной в верхнем регистре.
- `phone@1` — телефон хранится в формате E.164, с добавочным через `;ext=`.
  Пробелы, скобки, `00` и `#` нормализуются. Номер без «+» разбирается по
  `default_country` (по умолчанию `RU`; сейчас так читаются номера России и
  Казахстана).
- `url@1` — абсолютный адрес http(s) до 2048 байт, без логина и пароля.
- `link@1` — ссылка `{href, text?}`: абсолютный адрес http(s), путь от корня
  сайта или `#якорь`; адрес вида `//host` не принимается.

## Описание поля и панель свойств

Любое поле — поле Storage, настройка сайта, атрибут пользователя — описывается
одинаково: `PropertyField` (ключ, тип и версия, подпись, подсказка, настройки,
обязательность, только чтение, значение по умолчанию). Оформление — группа,
порядок, ширина — хранится отдельно, в `PropertyFieldPresentation`.

`PropertyViewFieldBuilder` превращает такое поле в то, что рисует компонент
Framework `sf-property-view`. Все панели свойств в админке строятся через него.
Условия показа поля (`when`) передаются вместе с ним.

Сейчас телефон и адрес рисуются как строки, а `link@1` — только для чтения:
своего элемента для ссылки в `sf-property-view` пока нет, значение меняется
через API.

## Отображение значения

`Larena\Property\Runtime\PropertyDisplayProjector` только читает: он превращает
проверенное сохранённое значение в простой текст с видом поля и статусом
`present`, `empty` или `unavailable`. Числа форматируются без плавающей точки.
Значение `lookup@1` показывается подписью из источника. Перед вставкой в HTML
текст нужно экранировать.

Для `file`, `relation` и `user` подпись даёт владелец данных через
`PropertyReferenceLabelResolver`; Property объявляет только интерфейс. В
`PropertyRenderContext` должны быть заданы `actorRef` и `scopeRef`. Если подписи
нет, значение получает статус `unavailable`: исходная ссылка никогда не
показывается вместо подписи.

## Общий стандарт с Bitrix

Типы свойств Larena и Bitrix (`simai.property`) описаны одним стандартом в
Specs: одинаковый смысл типа, одинаковая запись значения и проверочные примеры,
которые обе платформы прогоняют без изменений. Внутреннее устройство может
отличаться. `color`, `phone`, `url` и `link` добавлены в Larena по этому
стандарту.

Чего пока нет: типов `map` и `html`, регистрации своего типа из стороннего
пакета (реестр закрыт) и каталога шаблонов по типам.

## Ограничение

Property не хранит пользовательские значения и не назначает права. Новая схема
должна предпочитать `string@2`; совместимость старого типа не расширяет его
валидацию.
