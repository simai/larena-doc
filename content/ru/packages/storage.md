# `larena/storage`

> **Для кого:** разработчик данных. **Результат:** работать с версионированной
> записью через package runtime. **Источник:** package README, developer docs,
> Specs и Root tests. **Статус:** developer-testable persistent foundation.

Storage владеет структурами хранения, версиями схем и записей, а также
контролируемыми мутациями. Текущий интеграционный вход —
`Larena\Storage\Runtime\DatabaseStorageWorkbench`.

- Composer: `larena/storage`.
- Владелец: record/schema versions and mutations.
- Зрелость: developer-testable persistent foundation.

Пакет зависит от `larena/core`, `larena/property` и `larena/access`. Тип поля
сначала нормализует Property, решение операции принимает Access, затем Storage
создаёт или меняет запись с проверкой версии.

## Жизненный цикл данных

- Структуру можно архивировать и восстановить. Архивная структура сохраняет
  записи и историю, показывается в списке только по запросу и не принимает
  изменений.
- Окончательное удаление явное и касается только архивных данных:
  `purgeRecords()` удаляет архивные записи, `purgeStructure()` — архивную
  структуру со всеми записями. Удаляются все версии, локализованные значения,
  публикации и связи. Операция отклоняется, пока на удаляемые записи ссылается
  запись снаружи. Идентификатор удалённой структуры повторно не используется.
- `migrateStructure()` меняет структуру с перезаписью всех записей в одной
  транзакции: поле можно удалить, сменить ему тип или сделать обязательным.
  Если хотя бы одну запись нельзя преобразовать, ничего не записывается.
- Признак поля `hidden` влияет только на отображение; поле и значения остаются.
- `filterOperators()` сообщает, какие операторы фильтра доступны для каждого
  типа поля Property.

Кроме того, пакет реализует роли структур (`StructureRoleRegistry`), связи и
дерево записей без рекурсивного запроса (`RecordRelations`,
`AdminRecordTreeReader`), неизменяемые значения по локалям с цепочкой fallback
(`LocalizedValues`), публикацию ревизии по области и локали
(`PublicationLifecycle`) и чтение опубликованных данных (`ReadContracts`).
Отложенная публикация выполняется вызовом `sweep()`; команды или планировщика
для него пакет не поставляет.

Хранилищами и записями можно управлять в разделе Admin «Хранилища»
(`/admin/storage`). Типы `choice`, `choices` и `datetime` в этом разделе пока не
поддерживаются.

## Проверка

Root quality gate проверяет базовые мутации, CRUD и повторное чтение. Отдельный
hierarchy test ранее блокировался package test autoload в общей vendor-сборке;
не используйте его отсутствие как доказательство корректности иерархии.

## Ограничение

Прямой доступ к таблицам обходит версии, права и audit-контракт. Публичный
универсальный генератор моделей не принят в рамках двенадцати пакетов.

## Содержимое композиции

В профиле Minimal CMS Storage владеет структурированным содержимым и его
ревизиями. Layout хранит только типизированный `ContentBinding` с ожидаемой
ревизией. HTML не является форматом сохранения редакторского содержимого;
блочная модель может использовать JSON-подход EditorJS и проектироваться в
зарегистрированные компоненты при сборке.
