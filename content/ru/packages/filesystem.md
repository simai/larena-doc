# `larena/filesystem`

> **Для кого:** разработчик файловых функций. **Результат:** использовать
> логический файл через безопасный сервис. **Источник:** код пакета (`src/`),
> package README, CHANGELOG, Specs и integration evidence. **Статус:** guarded
> developer slice; версии файлов и поиск по содержимому проверены по коду
> `f2945aa1` 26.10.2026.

Filesystem владеет логическими файлами, их связью с хранилищем и безопасными
операциями жизненного цикла. Подтверждённая точка входа —
`Larena\Filesystem\Services\SafeFileService`.

Пакет зависит от Core и Access. Любая операция должна сохранить ограничение
пути, разрешение, связь с логическим объектом и возможность безопасного отказа.

## Замена содержимого и версии

Файл можно заменить новым содержимым, и он останется тем же файлом: логическая
ссылка, публичный адрес, имя, видимость и связи не меняются, поэтому страницы и
ссылки продолжают работать. Прежнее содержимое сохраняется как версия.

- `SafeFileService::replaceContent($logicalRef, $upload, $expectedSha256, $actorId)`
  заменяет содержимое. Новый файл должен иметь то же расширение. В
  `$expectedSha256` передаётся содержимое, которое видел человек: если файл
  успели изменить, замена отклоняется; то же самое содержимое ничего не меняет.
- `versions($logicalRef)` возвращает прежние версии, новые первыми.
- `restoreVersion($logicalRef, $version, $expectedSha256, $actorId)` возвращает
  версию. Ничего не теряется: текущее содержимое само становится новой версией.

Версии хранятся в таблице `larena_file_versions` и не удаляются. Содержимое
хранится по хешу, поэтому замена не стирает старые данные с диска.

## Поиск по содержимому и импорт

Для переноса файлов между сайтами (импорт SitePack хранилища)
`PortableLogicalFileStore` умеет:

- `contentMatches` — найти живые файлы с точно таким же текущим содержимым
  (SHA-256, размер, расширение), чтобы использовать уже имеющийся файл, а не
  создавать копию. Прежние версии в поиск не попадают. Ограничить поиск одной
  областью можно функцией-фильтром: привязка файла к области хранится в Core;
- `logicalRefTaken` и `publicIdTaken` — проверить, занята ли ссылка или
  публичный идентификатор, включая удалённые файлы;
- `PortableLogicalFileDescriptor::withIdentity` — импортировать файл под новой
  идентичностью. Импорт под публичным идентификатором чужого файла отклоняется с
  кодом `filesystem_portable_identity_conflict`.

## Проверка

В Root выполните:

```bash
php artisan larena:file-operation-guarded-flow-smoke
```

Ожидается `Status: PASS` для descriptor/session/storage flow, access/audit и
rollback/recovery boundaries.

## Ограничение

Полный браузерный upload/delete не принят для этой редакции. Guarded smoke не
равен готовому файловому менеджеру. Кнопки замены файла и истории версий
находятся в файловом менеджере, а не в этом пакете; Filesystem даёт только
сервис и хранение версий.

## Файлы в композиции

Композиция хранит только логические ссылки Filesystem. Физический путь,
credentials внешнего хранилища и временные URL в артефакт не записываются;
доступ к файлу проверяется владельцем при resolution или выдаче.
